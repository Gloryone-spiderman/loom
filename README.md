# 自由网络拓扑画布

这是一个使用 Vue 3 和 TypeScript 构建的本地自由网络拓扑画布，也是一个以理解和独立实现为目标的学习项目。

项目不追求一次性堆出完整产品，而是按照清晰的功能顺序逐步实现。每完成一项功能，都应能解释它使用的数据结构、状态变化、坐标计算和交互过程。

## 核心目标

让用户能够自由创建、编辑、连接和保存拓扑。

核心工作流：

```text
创建节点
-> 调整位置
-> 编辑内容
-> 建立连接
-> 保存拓扑
-> 导出展示
```

任何新功能开始前，都先判断它是否直接服务于这条核心工作流。不能明确服务于核心目标的功能，应延后或放弃。

## 产品目标

- 打开应用后直接进入自由画布。
- 不强制使用固定设备库。
- 双击画布任意位置创建通用节点。
- 支持选中、拖动、删除和重命名节点。
- 支持自由连接节点。
- 支持修改节点的形状、颜色和自定义属性。
- 支持撤销与重做。
- 支持保存和打开拓扑 JSON。
- 后期可以增加自动排布。
- 最后再考虑导出 ECharts 或 Avue 大屏配置。

## 第一版范围

第一版只实现：

- 自由创建节点。
- 拖动节点。
- 选中和删除节点。
- 修改节点名称。
- 节点连线。
- 保存和打开 JSON。

第一版暂时不做：

- 固定设备库。
- 后端服务。
- 用户登录。
- 多人协作。
- AI 自动生成拓扑。
- ECharts 或 Avue 导出。
- 复杂自动布局。

## 学习目标

完成项目后，应当能够独立解释：

- Vue 页面如何从 `index.html`、`main.ts` 启动并挂载 `App.vue`。
- Vue 响应式数据如何驱动节点和连线界面。
- 浏览器鼠标坐标如何转换成画布坐标。
- 节点拖动如何开始、更新和结束。
- 节点和连线分别如何建模。
- 画布状态如何序列化、保存和恢复。
- 第三方画布库解决了哪些底层问题。

并且能够独立完成：

- 新增功能。
- 修改交互。
- 定位错误。
- 更换画布方案。
- 判断何时需要 X6、ELK 或 Pinia。
- 在没有 AI 一次性生成整个项目的情况下继续开发。

## 开发原则

1. 每次只学习和实现一个可验证的小功能。
2. 修改代码前，先说清楚状态、事件和数据会如何变化。
3. 功能完成后，亲自操作并验证正常路径和边界情况。
4. 能够用自己的语言解释实现，再把进度标记为完成。
5. 第一版优先使用 Vue 自身能力；只有原生实现的复杂度已经成为问题时，才评估引入第三方方案。

## AI 使用边界

AI 可以：

- 解释概念和现有代码。
- 检查实现并指出具体问题。
- 给出调试方向和小范围提示。
- 帮助设计测试清单。
- 对技术方案进行比较。

AI 不应该：

- 一次性代写整个项目。
- 在没有讲清原理时连续添加多个功能。
- 用大型依赖掩盖尚未理解的基础问题。
- 代替开发者完成本应亲手进行的练习。

## 技术选择检查点

### 什么时候考虑 X6

当节点端口、连线交互、框选、组合节点、吸附和大量图编辑能力开始占用大量自研代码时，再评估 X6。第一版先通过基础实现理解图编辑器的核心机制。

### 什么时候考虑 ELK

当项目需要根据拓扑关系自动计算分层、方向和节点间距时，再使用 ELK。自由拖动画布本身不需要 ELK。

### 什么时候考虑 Pinia

当画布状态需要被多个页面或大量独立组件共同读写，且组件传递已经难以维护时，再引入 Pinia。单页面第一版可以先使用 Vue 的 `ref`、`reactive` 和组合式函数。
